# Фрагменты технического задания

[Скачать DOCX](excerpts.docx) · [Все примеры](../../README.md)

Подключение ИТ услуг и портал самообслуживания

Обезличенная выборка из технического задания. Представлены модель данных, права доступа, логика процесса и требования к интерфейсу. Названия платформы и подразделений заменены; из таблиц выбраны отдельные строки и колонки. Это фрагменты, а не полное техническое задание.

## 1 Атрибуты приложения Услуги

По разделу 4.3.2.1 исходного ТЗ. Приложение хранит услуги и сервисные операции поставщиков. Вкладки «Регламенты подключения» и «Шаблоны документов» доступны для услуг первого уровня.

| Атрибут | Тип поля | Правила заполнения и отображения |
| --- | --- | --- |
| Необходимо юридическое оформление? | Да/Нет | Доступно, если [Уровень услуги] = "1 уровень".<br>Вкладка «Регламенты подключения». |
| Тип подключения | Категория | Доступно, если [Необходимо юридическое оформление?] = "Да".<br>Для выбора доступны:<br>Оферта.<br>Соглашение.<br>Вкладка «Регламенты подключения». |
| Охват | Строка | Многострочный текст, доступно использование Markdown.<br>Доступно, если [Уровень услуги] = "1 уровень".<br>Расположение: вкладка "Регламенты подключения". |
| Порядок подключения | Строка | Многострочный текст, доступно использование Markdown.<br>Доступно, если [Уровень услуги] = "1 уровень".<br>Расположение: вкладка "Регламенты подключения". |
| Менеджер услуги | Пользователь | Доступно, если [Уровень услуги] = "1 уровень".<br>Расположение: вкладка "Основная".<br>Скрыть, если не заполнено. |
| Направление | Элемент приложения "Направления услуги" | Доступно, если [Уровень услуги] = "1 уровень".<br>Расположение: вкладка "Основная".<br>Скрыть, если не заполнено. |

Для выбранных полей «Необходимо юридическое оформление?», «Тип подключения», «Охват», «Порядок подключения» и «Направление» в исходной модели указана обязательность на формах создания и редактирования. Поле «Менеджер услуги» необязательное.

## 2 Права доступа к приложению Услуги

По разделу 4.3.2.1.3 исходного ТЗ. Доступ ограничивается на уровне элементов приложения. Ниже приведена выборка операций из исходной матрицы.

| Роль | Просмотр | Создание | Редактирование | Назначение прав | Управление процессами |
| --- | --- | --- | --- | --- | --- |
| Администратор | Да | Да | Да | Да | Да |
| Служба управления ИТ-услугами | Да | - | - | Да | Да |
| Подписант | Да | - | - | Да | - |
| Поставщики IT-услуг | Да | - | - | Да | - |
| Автор | Да | - | - | Да | - |

«Да» — право предоставлено; «–» — право не предоставлено. Администратор, служба управления ИТ-услугами и поставщики определяются группами. Подписант и автор определяются через атрибуты элемента.

В полной матрице дополнительно описаны удаление, экспорт, импорт и полный доступ. Эти колонки не включены в выборку.

## Правила отображения форм

Форма просмотра приложения «Услуги» аналогична форме создания. На вкладке «Основная» поля «Менеджер услуги» и «Группа обработки юридических документов» скрываются, если не заполнены. Поля доступны для услуг первого уровня.

## 3 Выбор сценария подключения услуги

По разделу 4.3.2.1.4.1 исходного ТЗ. Процесс запускается на портале из карточки выбранной услуги и определяет, требуется ли юридическое оформление подключения.

| Параметр | Описание |
| --- | --- |
| Инициатор | Пользователь портала с правами доступа на работу с офертами. |
| Входной параметр | Услуга, которую инициатор выбрал на портале. |

### Шаг 1 Проверка необходимости оформления

Система записывает значение поля услуги «Необходимо юридическое оформление?» в контекстную переменную процесса и переходит к проверке условия.

### Шаг 2 Выбор ветки процесса

| Ветка | Условие | Действие системы |
| --- | --- | --- |
| Нет | Ветка по умолчанию. | Запустить процесс «Подключение ИТ-услуги без юридического оформления». Завершить текущий процесс. |
| Да | Поле «Необходимо юридическое оформление?» имеет значение «Да». | Запустить процесс «Подключение ИТ-услуги, требующей юридического оформления». Завершить текущий процесс. |

Дальнейшее заполнение заявки, согласование и подписание документов выполняются в соответствующих дочерних процессах и в данный фрагмент не включены.

## 4 Требования к порталу самообслуживания

По разделам 4.6.1 и 4.6.2 исходного ТЗ.

### Сводный каталог ИТ услуг

- На странице должен быть фильтр «По направлениям / По поставщикам».

- В зависимости от выбранного фильтра отображается перечень услуг первого уровня.

- При нажатии на услугу открывается ее карточка. Необходимо предусмотреть закрытие карточки.

- Страница доступна пользователям, определенным в процессе создания оферты для получателя ИТ-услуг и записанным в поле организации «Ответственные за взаимодействие».

### Реестр подключенных ИТ услуг

На странице отображаются услуги, по которым есть заявки на подключение и юридические документы для организации текущего пользователя.

| Поле реестра | Источник или правило отображения |
| --- | --- |
| Наименование и тип услуги | Поля «Название» и «Тип услуги» из связанной услуги. |
| Поставщик и владелец | Поля «Поставщик» и «Владелец» из связанной услуги. |
| Инициатор подключения | Автор связанного юридического документа или заявки на подключение. |
| Юридический документ | Связанный документ организации в статусе «Действует». Если не найден — «Не требует». |
| Статусы | Статус связанного юридического документа и статус заявки на подключение. |
| Подписант и пользователи | Подписант юридического документа и объект доступности из этого документа. |
