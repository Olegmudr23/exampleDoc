# БП "Подписание оферты для Получателя IT-услуг"

[Каталог ТЗ](../README.md) · [Все примеры](../../../README.md)

Исходный раздел: **4.2.2.1.4.5**. Обезличенное описание из технического задания. Текстовые шаги, условия, параметры форм и таблицы перенесены без сокращения. Нумерация и проектные формулировки сохранены.

*Рисунок 10 — Схема бизнес процесса "Подписание оферты для получателя IT-услуг" — ссылка на рисунок исходного ТЗ; изображение в текстовую страницу не включено.*

В данном процессе исполнитель принимает участие в заключительном этапе формирования оферты, в результате которого документ будет подписан. Основное внимание уделяется проверке и заключению договора с получателем IT-услуг. Процесс запускается по кнопке "Отправить на подпись" на форме просмотра ("Статус" = "Новая", "Тип оферты" = "Для Получателя IT-услуг) оферты на портальной страничке.

## Зоны ответственности

Описание зон ответственности БП "Формирование оферты для получателя IT-услуг""

| Зона ответственности | Тип | Описание |
| --- | --- | --- |
| Получатель оферты | Динамическая | Инициатор, который запустил процесс по нажатию кнопки. |
| Подписант | Динамическая | Сотрудник, который является подписантом. |
| Оператор системы / Группа сопровождения | Статическая | Группа пользователей из Оператор системы/ Группа сопровождения |
| Ответственные за взаимодействие | Динамическая | Выбранные пользователи на форме заполнения оферты. |
| АИБы | Динамическая | АИБы подключаемой организации. |
| IT-сотрудники | Динамическая | IT-сотрудники подключаемой организации. |
| Сотрудники организации | Динамическая | Пользователи, которые относятся к организации. |


## Входные параметры

| Входной параметр | Описание |
| --- | --- |
| Подписант | Выбранный подписант в оферте. |
| Ответственные за взаимодействие | Выбранные ответственные в оферте. |
| Оферта | Элемент приложения "Оферты". |


## Шаги процесса

<a id="step-1"></a>
## Шаг 1 Присваивание "Автоматическое создание оферты"

Система автоматически сохраняет текущую оферту в том виде, которая была до нажатия на кнопку "Отправить на подпись". Далее переход на шаг 2.

<a id="step-2"></a>
## Шаг 2 Смена статуса "Оферта → Подписание"

Система автоматически сменяет статус оферты на "Подписание". Далее переход на шаг 3.

<a id="step-3"></a>
## Шаг 3 Задача "Подписать оферту"

Подписант (внешний пользователь) из оферты получает задачу на портал самообслуживания, чтобы подписать УКЭП (КриптоПРО) оферту.

| Параметр | Описание |
| --- | --- |
| Переназначение | Нет |
| Приложение | Оферта для CRM |
| Выход при успешном подписании | Шаг 6. |
| Выход при неуспешном подписании | Шаг 4. |
| Провайдер по умолчанию | КриптоПро |


На подписание дается 14 дней, в случае просрочки переход на шаг 4. Предусмотреть комментирование при отказе в подписании.

<a id="step-4"></a>
## Шаг 4 Смена статуса "Оферта → Корректировка"

Система автоматически сменяет статус оферты на "Корректировка". Далее переход на шаг 5.

<a id="step-5"></a>
## Шаг 5 Оповещение на email "Отправить email с отказом в подписании"

Cистема автоматически отправляет email получателю оферты:

| Получатель | [Получатель Оферты. Пользователь IT-услуг. Рабочая почта] |
| --- | --- |
| Тема сообщения | Оферта на подключение IT-услуг не подписана |
| Текст сообщения | Добрый день!<br><br>Ваша оферта не подписана по причине: $причина отмены.<br>Скорректируйте оферту по ссылке: $Ссылка на портальную страницу с формированной офертой. |
| Обработка ошибок | Завершение процесса. |


<a id="step-6"></a>
## Шаг 6 Смена статуса "Оферта → Подписана"

Система автоматически сменяет статус оферты на "Подписана" (Дополнительно: записать дату подписи в [Оферта. Дата подписи]). Далее переход на шаг 7.

<a id="step-7"></a>
## Шаг 7 Задача "Подтвердить корректность заполнения"

Пользователи из группы "Оператор системы / Группа сопровождения" получают задачу на подтверждение корректности заполнения.

| Параметр | Описание |
| --- | --- |
| Название по шаблону | Подтвердить корректность заполнения $(Название оферты) |
| Оповещение | Оповещать исполнителя о постановке задачи |
| Переназначение | Разрешить |
| Выполнять от имени | Система. |
| Правила исполнения | Кто первый? |
| Форма задачи | Описание |
| Оферта | Форма просмотра оферты. |
| Переходы | Подтвердить (Переход на шаг 11)<br>Отклонить (Переход на шаг 8) |


На подтверждение доступно 14 дней, иначе переход на шаг 8. Предусмотреть комментирование при отклонении.

## Шаг 8 Сценарий "Удалить файл УКЭП"

<a id="step-12"></a>
## Шаг 12 Сценарий "Проверить наличие подписки на CRM"

Система автоматически ищет запись в приложении [Доступность услуг. Объект доступности] = [Оферта организация], если в [Доступные услуги] существует запись "CRM", то переход на шаг 13. 
Иначе автоматически создает запись в [Доступность услуг. Объект доступности] = [Оферта организация] и [Доступные услуги] = "CRM." Далее переход на шаг 13.
