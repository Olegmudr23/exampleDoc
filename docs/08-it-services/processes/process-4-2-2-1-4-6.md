# БП "Подписание оферты для Внутреннего поставщика IT-услуг"

[Каталог ТЗ](../README.md) · [Все примеры](../../../README.md)

Исходный раздел: **4.2.2.1.4.6**. Обезличенное описание из технического задания. Текстовые шаги, условия, параметры форм и таблицы перенесены без сокращения. Нумерация и проектные формулировки сохранены.

*Рисунок 11 — Схема бизнес процесса "Подписание оферты для Внутреннего поставщика IT-услуг" — ссылка на рисунок исходного ТЗ; изображение в текстовую страницу не включено.*

В данном процессе исполнитель принимает участие в заключительном этапе формирования оферты, в результате которого документ будет подписан. Основное внимание уделяется проверке и заключению договора с поставщиком IT-услуг. Процесс запускается по кнопке "Отправить на подпись" на форме просмотра оферты для внутреннего поставщика IT-услуг  ( "Статус" = "Новая", "Тип оферты" = "Для Внутреннего поставщика IT-услуг) на портальной страничке.

## Зоны ответственности

Описание зон ответственности БП "Формирование оферты для получателя IT-услуг""

| Зона ответственности | Тип | Описание |
| --- | --- | --- |
| Получатель оферты | Динамическая | Инициатор, который запустил процесс по нажатию кнопки. |
| Подписант | Динамическая | Сотрудник, который является подписантом. |
| Ответственные за соглашения Оператора | Статическая | Группа пользователей из Оператора |
| Ответственные за взаимодействие | Динамическая | Ответственные за взаимодействие, указанные в оферте. |


## Входные параметры

| Входной параметр | Описание |
| --- | --- |
| Подписант | Выбранный подписант в оферте. |
| Ответственные за взаимодействие | Выбранные ответственные в оферте. |
| Оферта | Элемент приложения "Оферты". |


## Шаги процесса

<a id="step-1"></a>
## Шаг 1 Присваивание "Автоматическое создание оферты"

Система автоматически сохраняет текущую оферту в том виде, которая была до нажатия на кнопку "Отправить на подпись". Далее переход на шаг 2.

<a id="step-2"></a>
## Шаг 2 Смена статуса "Оферта → Подписание"

Система автоматически сменяет статус оферты на "Подписание". Далее переход на шаг 3.

<a id="step-3"></a>
## Шаг 3 Задача "Подписать оферту"

Подписант (внешний пользователь) из оферты получает задачу на портал самообслуживания, чтобы подписать УКЭП (КриптоПРО) оферту.

| Параметр | Описание |
| --- | --- |
| Переназначение | Нет |
| Приложение | Оферта для CRM. |
| Выход при успешном подписании | Шаг 6. |
| Выход при неуспешном подписании | Шаг 4. |
| Провайдер по умолчанию | КриптоПро |


На подписание дается 14 дней, в случае просрочки переход на шаг 4. Предусмотреть комментирование при отказе в подписании.

<a id="step-4"></a>
## Шаг 4 Смена статуса "Оферта → Корректировка"

Система автоматически сменяет статус оферты на "Корректировка". Далее переход на шаг 5.

<a id="step-5"></a>
## Шаг 5 Оповещение на email "Отправить email с отказом в подписании"

Cистема автоматически отправляет email получателю оферты:

| Получатель | [Получатель Оферты. Пользователь IT-услуг. Рабочая почта] |
| --- | --- |
| Тема сообщения | Оферта для Внутреннего поставщика IT-услуг не подписана |
| Текст сообщения | Добрый день!<br><br>Ваша оферта не подписана по причине: $причина отмены.<br>Скорректируйте оферту по ссылке: $Ссылка на портальную страницу с формированной офертой. |
| Обработка ошибок | Завершение процесса. |


<a id="step-6"></a>
## Шаг 6 Смена статуса "Обращение → Подписана"

Система автоматически сменяет статус оферты на "Подписана". Далее переход на шаг 7.

<a id="step-7"></a>
## Шаг 7 Задача "Подтвердить корректность заполнения"

Пользователи Ответственные за соглашения Оператора получают задачу на подтверждение корректности заполнения. Использовать автоматическое согласование.

| Параметр | Описание |
| --- | --- |
| Название по шаблону | Подтвердить корректность заполнения $(Название оферты) |
| Оповещение | Оповещать исполнителя о постановке задачи |
| Переназначение | Разрешить |
| Выполнять от имени | Система. |
| Правила исполнения | Кто первый? |
| Форма задачи | Описание |
| Оферта | Форма просмотра оферты. |
| Переходы | Подтвердить (Переход на шаг 11)<br>Отклонить (Переход на шаг 8) |


На подтверждение доступно 14 дней, иначе переход на шаг 8. Предусмотреть комментирование при отклонении.

<a id="step-8"></a>
## Шаг 8 Сценарий "Аннулировать файл УКЭП"

Система автоматически аннулирует УКЭП у оферты. Далее переход на шаг 9.

<a id="step-9"></a>
## Шаг 9 Смена статуса "Оферта → Корректировка"

Система автоматически сменяет статус оферты на "Корректировка". Далее переход на шаг 10.

<a id="step-10"></a>
## Шаг 10 Оповещение на email "Отправить email с отказом в согласовании"

Cистема автоматически отправляет email получателю оферты:

| Получатель | [Получатель Оферты. Пользователь IT-услуг. Рабочая почта] |
| --- | --- |
| Тема сообщения | Оферта для Внутреннего поставщика IT-услуг не согласована |
| Текст сообщения | Добрый день!<br><br>Ваша оферта не согласована по причине: $причина отклонения.<br>Скорректируйте оферту по ссылке: $Ссылка на портальную страницу с формированной офертой. |
| Обработка ошибок | Завершение процесса. |


<a id="step-11"></a>
## Шаг 11 Смена статуса "Оферта → Действует"

Система автоматически сменяет статус оферты на "Действует". Далее переход на шаг 12.

<a id="step-12"></a>
## Шаг 12 Сценарий "Получить ответственных за взаимодействие"

Система автоматически записывает в контекстную переменную группу пользователей, указанную из [Оферта. Ответственные за взаимодействие]. Переход на шаг 13.

<a id="step-13"></a>
## Шаг 13 Задача "Ознакомиться с онбордингом"

Пользователи, найденные на шаге 12 получают задачу:

| Параметр | Описание |
| --- | --- |
| Название | Ознакомиться с онбордингом |
| Оповещение | Оповещать исполнителя о постановке задачи |
| Переназначение | Нет. |
| Выполнять от имени | Система. |
| Правила исполнения | Параллельно |
| Форма задачи | Описание |
| Онбординг | Многострочный текст. |
| Переходы | Готово (Переход на шаг 14). |


<a id="step-14"></a>
## Шаг 14 Сценарий "Предоставить доступ к порталу потребителя IT-услуг"

Система автоматически всех ответственных за взаимодействие записывает в отдельный список сотрудников, которые имеют доступ к порталу потребителя IT - услуг.

| Параметр | Описание |
| --- | --- |
| Название | Пройдите онбординг |
| Оповещение | Оповещать исполнителя о постановке задачи |
| Переназначение | Нет. |
| Выполнять от имени | Система. |
| Правила исполнения | Параллельно |
| Форма задачи | Описание |
| Текст онбординга | Многострочный текст. |


Завершение процесса.
