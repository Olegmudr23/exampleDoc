# Бизнес-процесс "Внесение изменений в юридический документ"

[Каталог ТЗ](../README.md) · [Все примеры](../../../README.md)

Исходный раздел: **4.3.2.1.4.11**. Обезличенное описание из технического задания. Текстовые шаги, условия, параметры форм и таблицы перенесены без сокращения. Нумерация и проектные формулировки сохранены.

*Рисунок 30 — Схема бизнес процесса "Внесение изменений в юридический документ". — ссылка на рисунок исходного ТЗ; изображение в текстовую страницу не включено.*

Бизнес-процесс предназначен для внесения изменении в соглашение. Процесс запускается по кнопке "Внести изменение" на форме просмотра юридического документа, у которого "Статус" = "Действует" или "Отказ" и "Категория документа" = "Соглашение". Процесс запускается по кнопке "Внести изменения" (кнопка доступна только поставщикам).

## Зоны ответственности

Описание зон ответственности БП "Внесение изменений в юридический документ".

| Зона ответственности | Тип | Описание |
| --- | --- | --- |
| Инициатор | Динамическая | Пользователь портала по подключению IT-услуг. |
| Подписант | Динамическая | Подписант документа. |
| Дополнительный подписант | Динамическая | Подписант документа. |
| Поставщик IT-услуг | Динамическая | Пользователи, которые относятся к поставщику IT-услуг. |
| Подключенные сотрудники | Динамическая | Сотрудники подключаемой организации. |


## Входные параметры

| Входной параметр | Описание |
| --- | --- |
| Юридический документ | Юридический документ, который требует внесение изменений. |
| Инициатор | Поставщик. |


## Шаги процесса

<a id="step-1"></a>
## Шаг 1 Сценарий "Сгенерировать текст оферты"

Система автоматически записывает значение из [Услуга. Шаблон соглашения/оферты на внесение изменений на подключение IT-услуги] в контекстную переменную процесса. Далее переход на шаг 2.

<a id="step-2"></a>
## Шаг 2 Задача "Заполнить юридический документ"

Пользователь инициатор получает задачу на заполнение юридического документа:

| Параметр | Описание |
| --- | --- |
| Название по шаблону | Заполнить информацию для внесения изменений |
| Оповещение | Оповещать исполнителя о постановке задачи |
| Переназначение | Да |
| Выполнять от имени | Система. |
| Правила исполнения | - |
| Форма задачи | Описание |
| Текст юридического документа | Из шага 1 текст должен сгенерироваться по шаблону.<br>Доступно для редактирования текста. |
| Тип документа | "Доп. соглашение"<br>Недоступно для редактирования. |
| Подписант* | Элемент приложения "Внешние пользователи".<br>Для выбора доступен один пользователь. |
| АИБ | Список АИБов.<br>Заполнять автоматически из [Инициатор. Организация. Администраторы информационной безопасности]. (Недоступно для редактирования) |
| Ответственный IT | Список ответственных IT.<br>Заполнять автоматически из [Инициатор. Организация. Ответственные IT]. (Недоступно для редактирования) |
| Вложения | Из входного параметра.<br>Файлы. |
| IT-услуга | Из входного параметра. |
| Подписка | Для выбора доступно одно из значений:<br>Для всей организации;<br>Для структурной единицы;<br>Для конкретных пользователей.<br>Из входного параметра.<br>Недоступно для редактирования. |
| Объект доступности | Элемент приложения "Пользователи IT-услуг" или "Структурные единицы" или "Организации". Предусмотреть выбор только в рамках одного из справочника CRM.<br>Из входного параметра.<br>Недоступно для редактирования. |
| Переходы | Готово (Переход на шаг 3) (Доступно после заполнения всех полей).<br>Отменить (Завершение процесса). |


<a id="step-3"></a>
## Шаг 3 Сценарий "Получить группу поставщиков"

Система автоматически находит группу поставщиков, которая относится к услуге, указанной в документе и записывает в контекстную переменную процесса. Далее переход на шаг 4.

<a id="step-4"></a>
## Шаг 4 Смена статуса "Юридический документ → На рассмотрении"

Система автоматически изменяет статус документа на значение "На рассмотрении". Далее переход на шаг 5.

<a id="step-5"></a>
## Шаг 5 Задача "Рассмотреть доп. соглашение"

Пользователи полученные на шаге 3 получают задачу на рассмотрение соглашения:

| Параметр | Описание |
| --- | --- |
| Название | Рассмотреть доп. соглашение |
| Оповещение | Оповещать исполнителя о постановке задачи |
| Переназначение | Да |
| Выполнять от имени | Система. |
| Правила исполнения | Кто первый? |
| Форма задачи | Описание |
| Юридический документ | Форма просмотра элемента приложения "Юридический документ" |
| Переходы | Готово (Переход на шаг 8).<br>Отменить (Переход на шаг 6, предусмотреть комментарий обязательный). |


<a id="step-6"></a>
## Шаг 6 Смена статуса "Юридический документ → Отказ"

Система автоматически изменяет статус документа на значение "Отказ". Далее переход на шаг 7.

<a id="step-7"></a>
## Шаг 7 Уведомление "В заключении доп. соглашения отказано"

Система автоматически направляет инициатору сообщение. Далее завершение процесса.

| Параметр | Описание |
| --- | --- |
| Название | В заключении доп. соглашения отказано |
| Тема | В заключении доп. соглашения отказано |
| Текст сообщения | В заключении доп. соглашения: $(Юридический документ)отказано, в связи с: $(Комментарий, указанный на шаге 4). |
| Автор | Система. |
| Ассоциированный объект | Текущий процесс. |


<a id="step-8"></a>
## Шаг 8 Смена статуса "Юридический документ → На подписании"

Система автоматически изменяет статус документа на значение "На подписании". Далее переход на шаг 9.

<a id="step-9"></a>
## Шаг 9 Задача "Выбрать дополнительного подписанта"

Пользователи полученные на шаге 3 получают задачу на выбор дополнительного подписанта:

| Параметр | Описание |
| --- | --- |
| Название | Рассмотреть доп. соглашение |
| Оповещение | Оповещать исполнителя о постановке задачи |
| Переназначение | Да |
| Выполнять от имени | Система. |
| Правила исполнения | Кто первый? |
| Форма задачи | Описание |
| Дополнительный подписант* | Элемент приложения "Внешние пользователи".<br>Доступен выбор одного из значений. |
| Переходы | Готово (Переход на шаг 10) (Записать дополнительного подписанта в юридический документ). |


<a id="step-10"></a>
## Шаг 10 Задача "Подписать оферту"

Подписанты (подписант и дополнительный подписант) из юридического документа получает задачу , чтобы подписать УКЭП (КриптоПРО) оферту.

| Параметр | Описание |
| --- | --- |
| Переназначение | Нет |
| Приложение | Юридический документ |
| Выход при успешном подписании | Шаг 13. |
| Выход при неуспешном подписании | Шаг 11. |
| Провайдер по умолчанию | КриптоПро |


На подписание дается 14 дней, в случае просрочки переход на шаг 11. Предусмотреть комментирование при отказе в подписании.

<a id="step-11"></a>
## Шаг 11 Смена статуса "Юридический документ → Отказ"

Система автоматически изменяет статус документа на значение "Отказ". Далее переход на шаг 12.

<a id="step-12"></a>
## Шаг 12 Уведомление "В подписании доп. соглашения отказано"

Система автоматически направляет инициатору сообщение. Далее завершение процесса.

| Параметр | Описание |
| --- | --- |
| Название | В подписании доп. соглашения отказано |
| Тема | В подписании доп. соглашения отказано |
| Текст сообщения | В подписании доп. соглашения: $(Юридический документ)отказано, в связи с: $(Комментарий, указанный на шаге 9).<br>Причина: $(Из шага 9 или документ не подписан вовремя). |
| Автор | Система |
| Ассоциированный объект | Текущий процесс. |


<a id="step-13"></a>
## Шаг 13 Смена статуса "Юридический документ → Действует"

Система автоматически изменяет статус текущего документа на значение "Действует". Далее переход на шаг 14.

<a id="step-14"></a>
## Шаг 14 Сценарий "Раздать права на просмотр"

Система автоматически ищет из [Юридический документ. Услуга. Поставщик] соответствующую запись в группах и дает право на просмотр всем данным пользователям. Завершение процесса.
