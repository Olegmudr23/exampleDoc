# Бизнес-процесс "Расторжение в двустороннем порядке"

[Каталог ТЗ](../README.md) · [Все примеры](../../../README.md)

Исходный раздел: **4.3.2.1.4.10**. Обезличенное описание из технического задания. Текстовые шаги, условия, параметры форм и таблицы перенесены без сокращения. Нумерация и проектные формулировки сохранены.

*Рисунок 29 — Схема бизнес процесса "Расторжение в двустороннем порядке". — ссылка на рисунок исходного ТЗ; изображение в текстовую страницу не включено.*

Бизнес-процесс предназначен для отправки на подпись документа для Юридических документов, у которых "Категория документа" = "Расторжение" и "Статус" = "Новое" или "Отказ. Кнопка "Расторгнуть в двустороннем порядке" доступна всем пользователям, которые имеют доступ на просмотр (Поставщики и пользователи, которые работают на портале подключения IT-услуг".

## Зоны ответственности

Описание зон ответственности БП "Расторжение в двустороннем порядке".

| Зона ответственности | Тип | Описание |
| --- | --- | --- |
| Инициатор | Динамическая | Пользователь портала по подключению IT-услуг. |
| Подписанты | Динамическая | Подписант документа. |
| Поставщик | Динамическая | Поставщик IT-услуги |
| Дополнительный подписант | Динамическая | Внешний пользователь. |
| Сотрудники | Динамическая | Сотрудники отключаемой организации. |


## Входные параметры

| Входной параметр | Описание |
| --- | --- |
| Юридический документ | Юридический документ, который отправлен на подписание |
| Инициатор | Внешний пользователь, который работает на портале по подключению IT-услуг. |


## Шаги процесса

<a id="step-1"></a>
## Шаг 1 Присваивание "Записать категорию документа"

Система автоматически записывает из [Юридический документ. Категория документа] в контекстную переменную процесса. Далее переход на шаг 2.

<a id="step-2"></a>
## Шаг 2 Записать "Выбрать подписанта"

Инициатор получает задачу:

| Параметр | Описание |
| --- | --- |
| Название | Выбрать подписанта для документа о расторжении |
| Оповещение | Оповещать исполнителя о постановке задачи |
| Переназначение | Да |
| Выполнять от имени | Система. |
| Правила исполнения | Кто первый? |
| Форма задачи | Описание |
| Подписант | Доступен для выбора внешний пользователь. |
| Переходы | Готово (Переход на шаг 3) (Записать внешнего пользователя в Юридический документ).<br>Отменить (Завершение процесса). |


<a id="step-3"></a>
## Шаг 3 Шлюз "Соглашение?"

Инициатор получает задачу:

| Переход | Описание |
| --- | --- |
| Соглашение | [Категория документа] = "Cоглашение".<br>Переход на шаг 4. |
| Оферта | По умолчанию.<br>Переход на шаг 11. |


<a id="step-4"></a>
## Шаг 4 Смена статуса "Юридический документ → На рассмотрении"

Система автоматически изменяет статус текущего документа на значение "На рассмотрении". Далее переход на шаг 5.

<a id="step-5"></a>
## Шаг 5 Сценарий "Получить группу поставщиков"

Система автоматически находит группу поставщиков, которая относится к услуге, указанной в документе и записывает в контекстную переменную процесса. Далее переход на шаг 6.

<a id="step-6"></a>
## Шаг 6 Задача "Рассмотреть документ о расторжении"

Пользователи полученные на шаге 5 получают задачу на рассмотрение оферты:

| Параметр | Описание |
| --- | --- |
| Название | Рассмотреть документ о расторжении |
| Оповещение | Оповещать исполнителя о постановке задачи |
| Переназначение | Да |
| Выполнять от имени | Система. |
| Правила исполнения | Кто первый? |
| Форма задачи | Описание |
| Юридический документ | Форма просмотра элемента приложения "Юридический документ" |
| Переходы | Готово (Переход на шаг 9).<br>Отменить (Переход на шаг 7, предусмотреть комментарий обязательный). |


<a id="step-7"></a>
## Шаг 7 Смена статуса "Юридический документ → Отказ"

Система автоматически изменяет статус документа на значение "Отказ". Далее переход на шаг 8.

<a id="step-8"></a>
## Шаг 8 Уведомление "В расторжении отказано"

Система автоматически направляет инициатору сообщение. Далее завершение процесса.

| Название | В расторжении отказано. |
| --- | --- |
| Тема | Отключение IT-услуги |
| Текст сообщения | В отключении IT-услуги $(Услуга. Название) отказано, в связи с: $(Комментарий, указанный на шаге 6). |
| Автор | Система. |
| Ассоциированный объект | Текущий процесс. |


<a id="step-9"></a>
## Шаг 9 Смена статуса "Юридический документ → На подписании"

Система автоматически изменяет статус документа на значение "На подписании". Далее переход на шаг 10.

<a id="step-10"></a>
## Шаг 10 Задача "Выбрать дополнительного подписанта"

Пользователи полученные на шаге 5 получают задачу для выбора дополнительного подписанта:

| Параметр | Описание |
| --- | --- |
| Название | Выбрать дополнительного подписанта для соглашения |
| Оповещение | Оповещать исполнителя о постановке задачи |
| Переназначение | Да |
| Выполнять от имени | Система. |
| Правила исполнения | Кто первый? |
| Форма задачи | Описание |
| Юридический документ | Форма просмотра элемента приложения "Юридический документ" |
| Подписант* | Элемент приложения "Внешние пользователи".<br>Доступно для выбора одно из значений. |
| Переходы | Готово (Переход на шаг 11) (Записать "Подписант" в [Юридический документ. Дополнительный подписант]). |


<a id="step-11"></a>
## Шаг 11 Задача "Подписать документ на расторжение"

Подписант(ы) (подписант и дополнительный подписант) из юридического документа получает задачу , чтобы подписать УКЭП (КриптоПРО) оферту.

| Переназначение | Нет |
| --- | --- |
| Приложение | Юридический документ |
| Выход при успешном подписании | Шаг 14. |
| Выход при неуспешном подписании | Шаг 12. |
| Провайдер по умолчанию | КриптоПро |


На подписание дается 14 дней, в случае просрочки переход на шаг 12. Предусмотреть комментирование при отказе в подписании.

<a id="step-12"></a>
## Шаг 12 Смена статуса "Юридический документ → Отказ"

Система автоматически изменяет статус документа на значение "Отказ". Далее переход на шаг 13.

<a id="step-13"></a>
## Шаг 13 Уведомление "В подписании отказано"

Система автоматически направляет инициатору сообщение. Далее завершение процесса.

| Параметр | Описание |
| --- | --- |
| Название | В подписании отказано |
| Тема | Отключение IT-услуги |
| Текст сообщения | В отключении IT-услуги $(Услуга. Название) отказано.<br>Причина: $(Из шага 11 или документ не подписан вовремя). |
| Автор | Система |
| Ассоциированный объект | Текущий процесс. |


<a id="step-14"></a>
## Шаг 14 Смена статуса "Юридический документ → Подписано"

Система автоматически изменяет статус документа на значение "Подписано". Далее переход на шаг 15.

<a id="step-15"></a>
## Шаг 15 Смена статуса "Юридический документ → Расторгнуто"

Система автоматически изменяет статус документа из которого создан текущий документ на значение "Расторгнуто". Переход на шаг 16.

<a id="step-16"></a>
## Шаг 16 Сценарий "Автоматическое удаление подписок"

Система автоматически автоматически удаляет все подписки организации/структурной единицы/пользователя IT-услуги на IT-услугу. Далее переход на шаг 17.

<a id="step-17"></a>
## Шаг 17 Сценарий "Получить список сотрудников, которым уже недоступна услуга"

Система автоматически из доступности услуг получает список тех пользователей, которым была доступна услуга и записывает в контекстную переменную процесса. Далее переход на шаг 18.

<a id="step-18"></a>
## Шаг 18 Смена статуса "Юридический документ → Действует"

Система автоматически изменяет статус документа на значение "Действует". Далее переход на шаг 19.

<a id="step-19"></a>
## Шаг 19 Оповещение на email "Услуга отключена"

Cистема автоматически отправляет email полученным пользователям:

| Тема сообщения | Услуга отключена |
| --- | --- |
| Текст сообщения | Добрый день!<br><br>Теперь вы не можете формировать заявки по услуге $(Юридический документ. Услуга. Название) на портале самообслуживания. |
| Обработка ошибок | Завершение процесса. |
