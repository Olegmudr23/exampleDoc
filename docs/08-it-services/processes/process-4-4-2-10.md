## Запуск процесса

Инициатор — пользователь с правом создания заявок

## Шаги процесса

<a id="step-1"></a>
## Шаг 1 Шлюз: "Тип заявки"

Описания переходов в шлюзе.

| Переход | Условия |
| --- | --- |
| 1.1 Отмена заявки ДСТ | Система проверяет следующие условия:<br>Тип заявки = «Запрос на обсаживание»<br>Услуга = «СКЗИ VipNet»<br>Сервисная операция = «Выпуск» или «Отзыв», <br>Если условия выполнены, то процесс идет по данному переходу к шагу 2 |
| 1.2 ДСТ выпущен | Если условие 1.1 не выполнено, то процесс идет по данному переходу по стандартному пути исполнения заявки. |


<a id="step-2"></a>
## Шаг 2 Скрипт "Сохранить заявку"

В рамках выполнения скрипта система должна сохранить заявку в статусе "Новая" с заполнением следующих полей:

"Тема" заполнить значением "Выпуск ДСТ"

"Описание" заполнить значением "Выпуск ДСТ"

После выполнения скрипта процесс переходит к шагу 3.

<a id="step-3"></a>
## Шаг 3 Подпроцесс: "Обработка заявок VipNet"

Входные переменные.

| Процесс | Родительский |
| --- | --- |
| Инициатор | Инициатор |
| ДСТ | ДСТ |
| СО | Тип СО |


После завершения подпроцесса текущий процесс идет к шагу 4.

<a id="step-4"></a>
## Шаг 4 Шлюз: "Результат"

Описания переходов в шлюзе.

| Переход | Условия |
| --- | --- |
| 4.1 Заявка VipNet | Система проверяет результат обработки заявки. Если выпуск ДСТ был отменен, то процесс идет по данному переходу к шагу 5. |
| 4.2 Иное | Если условие 4.1 не выполнено, то процесс идет по данному переходу к выходу. |


<a id="step-5"></a>
## Шаг 5 Задача: "Заполнить заявку"

Название задачи "Заполнить заявку № {$номер заявки}".

В рамках задачи пользователь должен заполнить данные по заявке.

Описание параметров на форме задачи «Заполнить заявку».

| № п/п | Параметр | Тип | Обязательность | Видимость | Комментарий |
| --- | --- | --- | --- | --- | --- |
| 1 | Услуга | Приложение "Услуги" | Да | Да |  |
| 2 | Тема | Строка | Да | Да |  |
| 3 | Текст заявки | Строка | Да | Да |  |
| 4 | Тип заявки | Категория | Да | Да |  |
| 5 | Уровень воздействия | Приложение "Уровень взаимодействия" | Да | Да |  |
| 7 | Сервисная операция | Приложение "Услуги" | Да | Да |  |

Сохранить - процесс переходит к шагу 1.

Эскалация по таймеру (7 календарных дней) - процесс переходит к шагу 6.

Отмена - процесс переходит к шагу 6.

<a id="step-6"></a>
## Шаг 6 Скрипт "Изменить статус заявки"

В рамках выполнения скрипта система должна изменить статус заявки на "Отменена"

После выполнения скрипта процесс переходит к выходу.
