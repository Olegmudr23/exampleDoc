# Интеграция CRM и IP-телефонии

[Все примеры](../../README.md)

Контракт обмена с телефонией РТУ: операторы, звонки, уведомления и записи разговоров.

## Глоссарий 

**Call **(Звонок)

| **Переменная**   | **Тип** | **Описание**                                                     |
| :--------------- | :------ | :--------------------------------------------------------------- |
| protocolConfID   | string  | Идентификатор звонка, совпадает со значением в CDR               |
| source           | string  | Входящий (для АТС) номер звонка                                  |
| destination      | string  | Исходящий (для АТС) номер звонка                                 |
| user             | string  | Идентификатор сотрудника (абонента) ответившего/начавшего звонок |
| client           | class   | Клиент участвующий в звонке (если он известен)                   |
| direction        | string  | Направление вызова (incoming или outgoing)                       |
| durationSeconds  | int     | Продолжительность вызова в секундах                              |
| callRecord       | string  | Адрес для скачивания записи разговора                            |
| status <br>  | int     | Код завершения звонка                                            |

**User **(Сотрудник в CRM, абонент на РТУ)

| **Переменная** | **Тип** | **Описание**                                |
| :------------- | :------ | :------------------------------------------ |
| id             | string  | Идентификатор сотрудника в CRM              |
| phoneNumber    | string  | Номер телефона сотрудника (абонента на РТУ) |
| email          | string  | E-mail сотрудника                           |
| name           | string  | Полное имя сотрудника                       |
| sipLogin       | string  | Логин сотрудника для телефона               |
| sipPassword    | string  | Пароль сотрудника для телефона              |

**Client **(Лид, клиент, компания и т.п в CRM)

| **Переменная** | **Тип**  | **Описание**                                                                       |
| :------------- | :------- | :--------------------------------------------------------------------------------- |
| id             | string   | Идентификатор сотрудника в CRM                                                     |
| name           | string   | Имя клиента отображаемое на телефоне сотрудника при звонке                         |
| phoneNumbers   | string[] | Список номеров телефонов привязанных к клиенту                                     |
| vip            | bool     | Статус клиента (true или false), влияет на возможность вызова напрямую к менеджеру |
| user           | string   | Идентификатор сотрудника (абонента) ответственного за клиента                      |
| type           | int      | Tип клиента 0 - лид, 1 – не лид                                                    |

Абонент – рядовой пользователь в телефонии у которого не заполнен Id, и которой не может быть в роли оператора.

Оператор – пользователь в телефонии у которого заполнен Id, и которой может быть в роли оператора.

## Требования, цели, задачи и ограничения

## **Требования к разработке модуля интеграции**

- Реализация интеграционного взаимодействия между CRM и IP-ATC РТУ посредством API;
- Допускаются только асинхронные GET, PUT и POST запросы;
- Запросы должны обеспечить функциональность исходящих и входящих вызовов телефонии РТУ;
- Модуль интеграции должен уметь работать с несколькими доменами;
- Должна быть доступна возможность записи и прослушивания состоявшегося разговора.

## **Цели и задачи разработки модуля интеграции**

- Создание интеграционного взаимодействия с телефонией РТУ;
- Настроить интеграционный обмен между CRM и телефонией РТУ.

| Параметр | Значение |

```

**Response**

  "list": [

      "phoneNumber": "9976",
      "email": "operator1@example.com",
      "name": "Тестовый оператор 1",
      "sipLogin": "9976",
      "sipPassword": "DEMO_PASSWORD_1"
    },
    {
      "id": "12",
      "phoneNumber": "9972",
      "email": "operator2@example.com",
      "name": "Тестовый оператор 2",
      "sipLogin": "9972",
      "sipPassword": "DEMO_PASSWORD_2"
    }
  ],
  "code": 200,
  "reason": "OK"
}
```

Данный запрос вызывается из метода

```typescript
// Получить список пользователей IP-телефонии (используется для сопоставления пользователей по нажатию кнопки "Настроить" на странице модуля).
async function VoipGetMembers(): Promise<VoipMember[]> {
   throw new Error('Функция не реализована.');
}
```

При реализации данного метода реализован следующий функционал:

- Если несколько доменов, следовательно, абонентов необходимо получить из нескольких мест, для этого нужно отправить запросы во все известные домены и получить пользователей после чего, всех их собрать в один список и вернуть их для сопоставления с пользователями CRM.
- В карточке сопоставления отображены номер из телефонии, наименование пользователя, также добавить домен перед пользователем, к которому он относиться.
- Отфильтрованный список можно повторно использовать в дальнейшем в этом методе;
- В модуле есть возможно составить список сотрудников для удаления. Этот список нужно получить по нескольким правилам:
  - Пользователь должен быть заблокирован или не входить в группу операторов SD;
  - В элементе списка у него должно быть заполонено поле “Id”;
  - Список сотрудников для удаления, должен удовлетворять обоим этим правилам.

* Реализовано автоматическое сопоставление пользователей CRM и операторов телефонии по логину.

Данный запрос вызывается из метода

```typescript
// Получить список пользователей IP-телефонии (используется для сопоставления пользователей по нажатию кнопки "Настроить" на странице модуля).
async function VoipGetMembers(): Promise<VoipMember[]> {
   throw new Error('Функция не реализована.');

```

При реализации данного метода реализован следующий функционал:

- Если указано несколько доменов, то данные нужно отправлять в определённый домен по принципу, описанному выше;
- Данный запрос выполняется после завершения запроса "Запросить список сотрудников";
- Данный запрос выполняется для каждого пользователя из отфильтрованного списка из запроса "Запросить список сотрудников";
- В отфильтрованном списке перезаписывается поле “Id” и заполняется полем "phoneNumber" из этого же элемента списка, таким образом абонент становится оператором.

- Для реализации данного запроса используется кастомный метод API запроса "Звонок начался";
- Не используется авторизация;

- В случае некорректного номера в поле "destination" используется вместо него поле "user";
- Дальнейшая обработка этого запроса описана в методе ниже.

Данный запрос принимается в методе

```typescript
// Обработать запрос от провайдера IP-телефонии.
async function VoipParseWebhookRequest(request: FetchRequest): Promise<VoipWebhookParseResult>
```

При реализации данного метода учены следующие моменты:

- При окончании звонка, возвращается ссылка на разговор, которую можно получить в методе ниже:

```typescript
// Получить ссылку на запись звонка.
async function VoipGetCallLink(callData: any): Promise<string> {
   throw new Error('Функция не реализована.');
}
```

- В Body ответа присутствует атрибут "callRecord": [https://telephony.example.com:8431/download?crs=10000000000000000001&timeout=15](https://telephony.example.com:8431/download?crs=10000000000000000001\&timeout=15). Из этой строки удален timeout=15, чтобы ответ приходил без задержки соединений.

### Служебные процессы

#### Синхронизация справочника Операторы

Данный процесс необходим для поддержания актуальных данных операторов. При реализации процесса учтены следующие пункты:

- Процесс запускаться раз в сутки ночью;
- В процессе настроен цикл, в котором будут перебираться все домены из таблицы "Список доменов";
- По каждому домену происходит получения списка операторов и обновлением по ним данным операторов в приложении «Операторы»

| **Атрибут справочника (куда записи)** | **Атрибут запроса из телефонии (откуда записывать)** | **Примечание**                                                                                 |
| :------------------------------------ | :--------------------------------------------------- | :--------------------------------------------------------------------------------------------- |
| Оператор                              | -                                                    | Поиск пользователя по Email в CRM.                                                            |
| id<br>                            | id<br>                                           | Идентификатор оператора.                                                                       |
| phoneNumber                           | phoneNumber                                          | Номер телефона.                                                                                |
| Email                                 | email                                                | Электронная почта.                                                                             |
| name                                  | name                                                 | ФИО.                                                                                           |
| Домен                                 | -                                                    | Записывать значение домена из таблицы «список доменов», по которому сделали запрос в телефонию |
