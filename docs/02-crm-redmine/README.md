# Интеграция CRM и Redmine

[Полная текстовая версия](source.txt) · [Все примеры](../../README.md)

Модуль передает обращения из CRM в трекер задач, загружает вложения, получает статусы и комментарии. Ниже приведены основные положения и примеры из обезличенного документа; полная версия доступна по ссылке выше.

## Модель данных

| Поле CRM | Тип | Соответствие в Redmine |
| --- | --- | --- |
| Модуль | int | Проект |
| Краткое описание проблемы | string | Тема задачи |
| Описание решения | string | Описание задачи |
| Дополнительные файлы | string | Вложения |
| Приоритет | int | Приоритет задачи |
| Вид обращения | int | Категория |
| Продукт | {int, [string]} | Пользовательское поле «Бизнес» |
| Источник ошибки | {int, [string]} | Пользовательское поле «СК» |

Для поля «Ссылка на расчет» в исходной постановке тип указан как `string`, описание отложено.

## Настройки и авторизация

В настройках модуля задаются API endpoint и токен учетной записи. Права учетной записи определяют доступ к объектам интеграции.

Токен передается в заголовке `X-Redmine-API-Key`. Адреса в примерах демонстрационные.

Для вложений используется таблица расширений и MIME-типов, например:

| Расширение | MIME-тип |
| --- | --- |
| pdf | application/pdf |
| png | image/png |

В настройках необходимо предупредить пользователя о возможном повреждении файла при передаче расширения, которого нет в таблице. Если MIME-тип не найден, исходная постановка предусматривает передачу пустого `content_type`.

## Методы API

| Операция | Метод | Путь |
| --- | --- | --- |
| Создать задачу | POST | `/issues.json` |
| Загрузить файл | POST | `/uploads.json?filename={filename}` |
| Получить задачу и журнал | GET | `/issues/{id}.json?include=journals` |
| Добавить комментарий | PUT | `/issues/{id}.json` |

Базовый адрес: `https://tracker.example.com`.

### Создать задачу

Данные формируются из контекста процесса «Передать на вторую линию». Для ссылочных полей CRM извлекается атрибут «Id в Redmine» соответствующего элемента.

**Пример тела запроса**

```jsonc
{
  "issue": {
    "category_id": 1,
    "custom_fields": [{
      "id": 2,
      "value": ["ВСЕ"]
    }, {
      "id": 1,
      "value": ["Страховая компания А"]
    }
  ],
  "description": "Здесь описание задачи",
  "priority_id": 2,
  "project_id": 1,
  "subject": "Тестовая задача через интеграцию"
  "uploads": [
    {
      "token": "1000.00000000000000000000000000000000",
      "filename": "image.png",
      "content_type": "image/png"
    }
  ]
}
}
```

`category_id` — вид обращения; `project_id` — модуль; `priority_id` — приоритет. В `custom_fields` передаются дополнительные поля. Блок `uploads` содержит токены предварительно загруженных файлов.

### Загрузить файл

Тело запроса — бинарные данные файла без преобразований. Заголовок `Content-Type`: `application/octet-stream`. Имя файла передается в параметре `filename`, включая расширение.

**Пример ответа**

```jsonc
{
  "upload":
  {
    "token":"1000.00000000000000000000000000000000"
  }
}
```

Полученный токен передается в `uploads` при создании задачи.

### Добавить комментарий

**Пример тела запроса**

```jsonc
{
  "issue": {
    "notes": "Обычный коммент",
  }
}
```

Успешный ответ — HTTP `204`. Модуль ожидает успешного завершения запроса. Комментарий также записывается в ленту обращения CRM. В исходном документе предусмотрен маркер изображения в начале комментария; его адрес должен уточняться перед реализацией.

## Процесс синхронизации

1. Пользователь запускает «Передать на вторую линию» из карточки обращения. Кнопка доступна, пока ID задачи в Redmine не заполнен.
2. Пользователь заполняет стартовую форму; система загружает файлы и создает задачу.
3. Идентификатор и дата создания сохраняются в контексте процесса и в обращении.
4. Система циклически получает задачу, обновляет статус и проверяет новые публичные комментарии.
5. Новые комментарии добавляются в ленту от имени системы с указанием автора из трекера. Для защиты от дублей хранится массив ID комментариев.
6. При появлении `closed_on` система сохраняет дату закрытия, выходит из цикла и вычисляет длительность обращения и ожидания первого ответа в минутах.

Дополнение исходной постановки требует передавать `updated_on` в активити как дату и время.

## Данные процесса и справочники

В контексте хранятся модуль, ссылка на расчет, краткое описание, описание решения, файлы, приоритет, вид обращения, продукт и источник ошибки. Для синхронизации используются ID задачи, статус, даты открытия и закрытия, дата первого ответа и таблица комментариев.

В справочники «Модули», «Продукт», «Источник ошибки» и «Виды обращений» добавляется строковый атрибут «Id в Redmine».

## Об оформлении примеров

Структура полей и значения взяты из исходного документа. Блоки `jsonc` показывают примеры постановки; перед использованием в запросах их необходимо привести к валидному JSON. Полный исходный текст с деталями форм и процесса сохранен отдельно.
